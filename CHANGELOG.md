# Changelog

## Unreleased

### Changed

- **Task resources matched to what the tools use** (measured with SLURM accounting on the Oct 2026 runs). BLASTsearch, BLASTparalogs and BlastLocusOnReference use 1 CPU (they kept ~1 of 4 cores busy); fastp 8 (was the profile default, 16 on SLURM); AlignBuscoGene 4 (was 16, for seconds-long alignments); the per-query IQ-TREE trees 4, with `-T AUTO` picking the thread count up to that; BUSCO 8 CPUs and 8 GB (was 2 CPUs and 4 GB, CPU-bound and at its memory limit); RAxML-NG 8 GB (was 32 GB, peak 3 GB); CombineBlastHits 2 GB (was 8 GB). Resources are now set only in `nextflow.config`, no longer partly in the modules where the config silently overrode them.
- **`--max_cpus`, `--max_memory`, `--max_time`** (defaults 16, 128 GB, 7 days) cap every task's request. Memory doubling on retries could previously exceed any node (SPAdes up to 96 GB, RAxML-NG up to 192 GB) and leave the job pending.
- **`pipeline_trace.txt` records `%cpu` and `%mem`**, so CPU use can be checked without SLURM accounting.

### Fixed

- **Protein translated in the wrong frame when a model's 5′ end is offset.** Exonerate can begin an alignment part-way through a query codon (`coding2genome` reporting e.g. `vulgar: AvrStb9_CDS 2 2183 +`, i.e. from the third base of codon 1). The assembled CDS then opened with an incomplete codon, and `extract_exonerate_cds.py` translated it from base 0, shifting the protein out of frame. On a 4,068-genome panel this hit 4,020 of 4,070 models of one effector, whose stored protein was a 37-aa frameshifted fragment while the CDS beside it was correct and every metric in the same row described a full-length product. The partial leading codon is now dropped, so the CDS stays in frame and the protein is `translate(cds)`. Everything built from the protein is affected: `{query_id}_exonerate_protein.fasta`, the protein isoform numbering, `{query_id}_protein_isoforms.fasta`, the protein alignments and the protein trees.
- **A single non-canonical splice site made every sample "truncated".** `classify_cds_integrity.py` counted a non-canonical splice site as an ORF mutation, which alone set the status to `truncated`. An exon boundary placed one or two bases off reads as a non-canonical acceptor while leaving the protein untouched, and such a call is typically shared by every sample: one `AG>CA` acceptor at the same position made 100 % of a 4,068-genome panel truncated for one effector and left its intact-only isoform table with a single row. The site is still reported in `orf_mutation_types`, `n_noncanonical_splice_sites` and the mutation table, but on its own, with the reading frame still reaching the expected stop, the status is now `full_length` with the note `noncanonical_splice_site_only_ORF_intact`, or `partial` when the model is also cut off by a contig edge or an assembly gap. (The first version of this fix called such incomplete models `full_length`, e.g. two AvrStb9 models missing 43 and 92 N-terminal residues at a contig end.)

- **RepeatMasker ran 4× more threads than allocated.** `-pa` sets parallel batches, and RepeatMasker runs each RMBlast batch with 4 threads, so `-pa 2` started 8 threads on 2 cores. It now gets 4 CPUs and `-pa` is the CPU count divided by 4.
- **fasterq-dump ran 6 threads on 1 CPU** (its default). It now uses the task's CPUs (`-e`).
- **samtoolsSort ran up to 4 threads on 1 CPU** (`-@` counts additional threads, and `view` and `sort` each got their own). It now gets 4 CPUs, uses `-@ cpus-1`, streams uncompressed BAM from `view` to `sort`, and sets the sort memory per thread from the task memory.

- **Paralog hits contaminated the downstream outputs (`--query_paralog`).** The paralog check ran after the hit extraction and only reported, so in a sample without the query gene the query's best BLAST hit on a paralog was still extracted, modelled by Exonerate (often as "full_length"), classified, numbered as an isoform and placed in the alignments and trees. The check now runs per sample before the extraction: every BLAST hit is assigned to the query or to the paralog that scores best there, and only the query's own copy is extracted. Samples whose query hits are all paralog loci are `paralog_only` in the BLAST and Exonerate summaries, the isoform table and the TE summary, and are absent from all sequences, alignments and trees. Exonerate gene models must now overlap the extracted BLAST hit span, so a paralog in the padding flank is not modelled.
- **Neighbouring paralogs could still enter the query's gene model and CDS integrity call (`--query_paralog`).** The extracted window (hit ± `--padding`) and the CDS integrity rescue search (up to 3 kb of flanking contig) could reach a paralog copy next to the query copy. Exonerate could then fuse the paralog to a truncated query copy (only models lying entirely in the flank were discarded), and a missing query segment found in the paralog was reported as present on the contig (`segment_outside_ORF`, an ORF mutation) instead of a nucleotide deletion. `ResolveParalogs` now passes the paralog copies on the hit scaffold to the extraction, which stops the padding short of them and lists them in the hit FASTA header (`paralogs=start-end,...`); the CDS integrity check masks them for its rescue search and notes `paralog copy in flank not searched` on the resulting deletion. This also keeps paralog sequence out of the padded BLAST hit sequences, alignments and trees.
- **Locus coverage could be measured at a paralog (`--query_paralog` with `--locus_coverage`).** The reference locus was the query's best BLAST hit on the reference, which lies on a paralog when the reference has no copy of the query. The paralogs are now BLASTed against the reference as well, and a locus where a paralog hit scores higher is dropped (coverage `NA`).
- **TE summary did not tell paralog-only samples from samples without a hit.** `{query_id}_scaffold_TEs_summary.tsv` has a new last column `hit_status` (`hit`, `no_hit`, `paralog_only`); the per-TE table already marked them in `position`.
- **Paralog table reported paralogs incompletely.** A paralog's "best locus" merged all its hits on a scaffold, so neighbouring paralogs were reported as one locus and the second paralog's own copy was hidden (in IPO323, paralog1's locus spanned both chromosome-10 genes). Every reference's copies are now separated by hit ownership; `{query_id}_paralog_check.tsv` lists for the query and every paralog the number of copies and the best one, and the new `{query_id}_paralog_loci.tsv` lists every copy of every reference per sample. New column `skipped_paralog_loci` lists query hit loci left out because a paralog scores higher there.

- **CDS check of multi-sequence queries with `--search_tool exonerate`.** The startup check for in-frame stop codons joined all query sequences into one, so the terminal stop codon of the first CDS counted as an internal stop and a valid multi-CDS query file was rejected. Each query is now checked on its own, and the error names the offending query.

## v0.9.1 — 2026-10-15

Pre-release: functional but not yet fully tested.

### Added

- **Paralog check (`--query_paralog`).** A FASTA of known paralogs, named after their query plus `_paralog1`, `_paralog2`, … (checked at startup, including the sequence type). The paralogs are BLASTed against every assembly, and `13_summary_data/{query_id}_paralog_check.tsv` reports per sample whether the hit reported for the query is closest to the query or to one of the paralogs (`call`: `query`, `paralog`, `ambiguous`, `no_hit`), with bit score, identity and coverage of every reference at the hit locus and the paralogs' own best loci. `--paralog_ambiguous_ratio` (default 0.95) sets when a call is ambiguous.
- **Alignment filter for the per-query trees (`--min_align_prop`, default 0.8).** Sequences covering less than this proportion of the core alignment are left out of the BLAST, CDS, protein and isoform trees. The core is the columns of the query reference, or, without it, the columns where at least half of the sequences have a residue, so that a single long outlier cannot exclude all other sequences. The query reference is always kept. `9_phylogenies/.../*_phylogeny.alignment_filter.tsv` lists the decision for every sequence; `*_phylogeny.filtered_alignment.fasta` is the tree input.
- **Contig edges and ORF ends in the CDS integrity tables.** A gene model that is incomplete only because it runs off the contig (or reaches an assembly gap) now has status `partial` instead of `truncated`, with `truncation_cause` `contig_edge` / `assembly_gap` instead of `nucleotide_deletion`. New columns: `contig_edge` (which end runs off the contig), `orf_end` (`expected_stop`, `premature_stop` = ORF cut short, `late_stop`, `contig_end`), `contig_flank_5prime_nt` / `contig_flank_3prime_nt` (contig sequence beyond the coding part). Partial isoforms are excluded from the intact-only table and drawn grey in the isoform trees.
- **`sample_names.tsv`** in the output folder maps every input to its `--SRR_sample_map` name and final sample name.
- **Truncated isoforms.** Every Exonerate CDS is classified as full-length, truncated or stop-lost (`extended`), separating nucleotide-level deletions (query segment absent, contig end, assembly gap) from ORF mutations (frameshift, premature stop, lost start/stop codon, non-canonical splice site). New outputs in `13_summary_data/`: `{query_id}_isoforms_incl_truncated.tsv` (all sequences with isoform IDs, status and mutations; samples without a hit listed as `no_hit`) and `{query_id}_isoform_mutations.tsv` (one row per mutation with query position, contig coordinates and codon change). `{query_id}_isoforms.tsv` now holds intact isoforms only.
- **Isoform sequences.** `13_summary_data/{query_id}_cds_isoforms.fasta` and `{query_id}_protein_isoforms.fasta` hold one sequence per unique isoform, with the number of samples and their status in the header. The isoform tables also have `cds_sequence` and `protein_sequence` columns.
- **Isoform trees.** IQ-TREE trees with one tip per CDS and per protein isoform (`9_phylogenies/exonerate/{query_id}/{query_id}_{cds,protein}_isoform_phylogeny.*`), built from `13_summary_data/{query_id}_{cds,protein}_isoforms_aligned.fasta`. Each tree is also drawn as a midpoint-rooted PDF, with tips labelled by isoform number and sample count, truncated isoforms coloured, the reference marked and bootstrap support shown. Requires at least 3 isoforms. Uses the `bioconductor-ggtree` container (R/ape).
- **TEs near the hit.** With `--repeat_library` and `--blast_query`, `13_summary_data/{query_id}_scaffold_TEs.tsv` lists every TE on the scaffold carrying each sample's hit (Exonerate gene model, or best BLAST hit), with class/family, strand relative to the hit, and edge-to-edge distance in the hit's 5'→3' orientation (negative = upstream, positive = downstream, 0 = overlap). `{query_id}_scaffold_TEs_summary.tsv` gives one row per hit with the overlapping and nearest upstream/downstream TEs. RepeatMasker `.out` tables are now kept in `12_repeatmasker/`.
- **Sample name collision check.** The run stops before assembly when two inputs (reads, SRA runs, scaffolds) end up with the same sample name, including after `--SRR_sample_map` renaming or after characters outside `[A-Za-z0-9._-]` are replaced by `_`. The error lists the clashing inputs. Before, their outputs overwrote each other and IQ-TREE failed on duplicated names.
- **`--exonerate_refine`** (`region` default, `full`, `none`) sets how Exonerate refines its alignment (see Fixed).

### Changed

- **SLURM submission throughput.** Nextflow now submits up to 240 jobs per minute (was 60) and keeps up to 500 in the queue (was 300).
- **Sample names are made filesystem-safe at input.** Characters outside `[A-Za-z0-9._-]` are replaced by `_` in sample names for all steps and outputs (`Iran_2024_Kch(2)12-1g` → `Iran_2024_Kch_2_12-1g`); tree tips already showed these names. See Fixed.
- **README restructured.** One table of pipeline steps; options grouped by purpose in tables with their defaults and requirements; outputs listed per folder; one methods section instead of descriptions repeated under options and outputs. Corrected: profile CPUs and the default profile, the genome-wide depth statistic of `--locus_coverage`, BUSCO protein (not nucleotide) sequences for the species tree, the BUSCO download location, and outputs that were missing (fastp JSON reports, run statistics, query sequences, BWA summary text).
- **Isoforms are numbered by frequency.** Before, the query reference was isoform 1, and the others were numbered in alphabetical order of the samples. Now intact isoforms come first, ordered by the number of sample sequences carrying them, so the most frequent is isoform 1. They are followed by the query reference if no intact sample shares it, then by isoforms found only in truncated or stop-lost sequences, again by frequency. The intact-only table numbers consecutively. Numbering is shared by all isoform files.
- **Sequence names are sample IDs throughout.** Protein headers no longer carry a `_prot` suffix (they match the CDS: `sample_id`, or `sample_id_N` for several gene models; the translated nucleotide query is named by the first word of its header). In the combined BLAST hit FASTA, each hit is named by its sample ID with its location as description (`>sample_id scaffold:start-end`). MAFFT's `_R_` reverse-complement prefix is removed from all alignments and listed in the MAFFT log. Alignments and trees therefore show sample names.
- **Documentation of the per-query trees.** The README said the Exonerate CDS/protein trees require `--phylo_tree`. They are in fact always built with `--search_tool exonerate`, and `--phylo_tree` requires `--busco_lineage`, so the documented example failed. The README now describes the actual behaviour, and gives the RAxML-NG BUSCO model consistently as LG+G.

### Fixed

- **Samples with special characters in their name lost their hits.** Nextflow backslash-escapes staged file names, so a quoted path such as `"Iran_2024_Kch\(2\)12-1g_blast_results.tsv"` was not found: hit extraction silently wrote an empty FASTA, and the CDS integrity step failed. Sample names are now safe at input (see Changed), and staged paths in hit extraction and CDS integrity are no longer quoted, which also covers assembly files with such characters.
- **Contig ends reported as lost start or stop codons.** When the contig ended right at a short unaligned terminus or before the stop codon, the model was reported as `start_lost` / `stop_lost` (an ORF mutation, status `extended` for the stop). These are now contig edges (status `partial`). A reading frame that runs into the contig end without a stop codon reports its protein length as a minimum (`>=N`).
- **TEs near the hit missing on large datasets.** The step loaded the RepeatMasker tables of all samples completely and ran out of memory (its 2 GB limit did not grow on retry), so the `*_scaffold_TEs*.tsv` tables were silently not written. It now keeps only the TEs on the hit scaffolds, and its memory grows on retry.
- **`--NCBI_API_key` had no effect.** The key was printed but never passed to the SRA lookup. It is now given to `entrez-direct` (`NCBI_API_KEY`), and the startup summary shows only whether a key is set instead of the key itself.
- **BLAST hit tree failed or was unreadable.** BLAST hits were named only by scaffold location, so tree tips did not show the sample, and IQ-TREE failed when two samples shared a scaffold name and location.
- **Exonerate with nucleotide CDS queries returned no hits.** Nucleotide queries now use the `coding2genome` model instead of `est2genome`. `est2genome` reported the aligned region as UTR/exon and emitted no CDS features, so nothing was extracted even when the exon structure was found. Separate alignments on the same target are no longer merged into one gene model, and only the best-scoring model is kept where alignments overlap.
- **Exonerate dropped exons of divergent alleles.** Exonerate now refines its heuristic alignment (`--refine region`). Before, intact but divergent alleles often came out as single-exon fragments and looked truncated.
- **Antisense CDS models.** For nucleotide queries, `coding2genome` alignments of the reverse-complemented query are no longer extracted. At divergent loci they could outscore the sense model and replace it.
- **Nucleotide BLAST missed divergent or short-exon hits.** `blastn` now runs with `-task blastn` instead of the megablast default.

## v0.9.0 — 2026-09-17

First tagged pre-release. The pipeline is functional but not yet fully tested; see `FUTURE_FEATURES.md` for planned work.

### Features

- **Input options.** Start from local paired-end FASTQ files, NCBI SRA accessions (metadata via `entrez-direct`, download via `sratools`/ENA), or pre-assembled scaffolds.
- **Read QC and assembly.** `fastp` trimming and quality filtering with a per-sample read statistics table; `SPAdes` de novo assembly (`--isolate`).
- **Assembly QC.** `QUAST` metrics and optional `BUSCO` completeness (`--busco_lineage`, `--busco_subsample`).
- **Query search.** `BLAST` (blastn/tblastn, auto-detected from the query FASTA) with hit extraction and `MAFFT` alignments; optional `Exonerate` spliced alignment with CDS/protein extraction (`--search_tool exonerate`).
- **Isoform / haplotype identification.** Consecutive isoform IDs for unique CDS and protein sequences per query.
- **Phylogenetics.** Maximum-likelihood tree from BUSCO single-copy orthologs (`--phylo_tree`; RAxML-NG default, IQ-TREE 3 via `--busco_tree iqtree`) and per-query IQ-TREE trees from Exonerate alignments.
- **Reference mapping.** Optional `bwa-mem2` mapping to a reference genome (`--reference_genome`) with % mapped reads and locus coverage relative to the genomic background (`--locus_coverage`).
- **Repeat annotation.** Optional `RepeatMasker` with a user-provided consensus library (`--repeat_library`).

### Infrastructure

- Numbered output directories following the order of the pipeline.
- Cluster-agnostic SLURM profile (`--slurm_queue`), plus `local` and `local_highCPU` profiles.
- Standardised retry and error strategies with incremental memory on retry.
- Sample IDs sanitised for tools that reject spaces or special characters in paths.
- Nextflow 26 language compatibility.
